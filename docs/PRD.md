## 1. 개요

- **한 줄 정의**: Smalltalk Today는 오늘의 뉴스를 직장인이 바로 써먹을 수 있는 자연스러운 스몰토크 문장으로 변환해주는 AI 기반 웹앱이다.
- **배경**: 정보 과다 시대에 뉴스를 읽는 것과 그것을 일상 대화로 연결하는 것 사이에는 큰 간극이 존재한다. 20-30대 직장인은 매일 뉴스를 접하지만, 그것을 회의 전/점심/티타임의 스몰토크로 자연스럽게 꺼내는 데 인지적 부담과 불확실성을 느낀다.
- **목표**: MVP를 통해 "AI가 생성한 스몰토크 문장이 실제 대화 상황에서 유용하게 쓰이는가"를 검증한다.
- **대상 사용자**: 20-30대 직장인 (이 외에도 모임, 소개팅, 네트워킹이 잦은 사용자에게도 확장)

## 2. 3C 분석

- **Customer**: 20-30대 직장인. 뉴스를 알지만 대화로 꺼내기 어려운 사람. 아침 출근 전/점심/티타임에 모바일로 콘텐츠 소비.
- **Competitor**: 네이버 뉴스 (정보 제공만, 대화화 없음), GPT/Claude 직접 사용 (진입 장벽 높음), 뉴스레터 (읽기 중심, 대화화 없음)
- **Company**: 린 스타트업 방식. 빠른 가설 검증, 개발 리소스 최소화, 확장성보다 구현 단순성 우선.

## 3. 문제 정의

### 3.1 핵심 페인포인트 (사용자 인터뷰·관찰)

- **표현 피로**: 뉴스는 넘치지만 일상 대화로 연결하기 어렵다. 기사체 문장을 구어체로 바꾸는 것이 번거롭다.
- **인지 부담**: "이 이야기를 꺼내도 될까?" 하는 판단 부담. 주제 선정, 맥락 파악, 문장 생성을 모두 혼자 해야 한다.
- **사용 맥락 불일치**: 기사를 읽는 시점(출근 전)과 대화를 나누는 시점(점심/티타임)이 달라 읽어도 기억에 남지 않는다.

### 3.3 문제 최종 정의

직장인은 매일 뉴스를 접하지만, 그것을 자연스러운 스몰토크 대화로 연결하는 과정에서 인지적 부담과 불확실성을 느낀다. 이들은 정보를 모르는 게 아니라, 알고 있는 것을 말로 꺼내는 데 확신이 없다.

## 4. 해결 방안

## 6. 사용자 스토리 및 수용 기준

### US-01. 오늘의 대화 주제 확인

사용자로서 사이트에 들어오자마자 오늘의 대화 주제를 확인하고 싶다. 고민 없이 바로 대화를 시작하기 위해서다.

- 접속 시 3초 이내에 오늘 뉴스 카드가 표시된다
- 첫 화면 콘텐츠는 미리 생성되어 로딩 없이 표시된다 (사전 생성 방식)
- 진입 시 로그인 팝업이 뜨지 않는다
- 최소 3개 이상의 카드가 보인다
- 랭킹 탭에서 오늘 대화 소재 TOP 10을 확인할 수 있다

### US-02. 이슈 맥락 파악 + 스몰토크 확인

사용자로서 뉴스 맥락을 간단히 파악한 뒤, 스몰토크 문장을 확인하고 싶다. 배경 이해 없이 문장만 외우는 부담을 줄이기 위해서다.

- 이슈 요약은 기본 접힌 상태, 확장 클릭 시 전체 표시
- 스몰토크 문장은 항상 보이는 상태로 유지
- 요약은 3줄 이내
- 스몰토크 문장은 전문 용어 없이 구어체로 작성됨

### US-03. 문장 저장 및 활용

사용자로서 마음에 드는 문장을 저장해두고 나중에 꺼내 보고 싶다. 필요한 순간 바로 활용하기 위해서다.

- 저장 버튼 클릭 시 localStorage에 저장되며 시각적 피드백 제공
- 다시 방문해도 저장 문장이 유지됨
- 저장 항목은 하단 내비게이션의 저장 탭에서 확인 가능
- 저장 시 다음 데이터 함께 저장: 스몰토크 표현 4개와 보던 표현 순서, 뉴스 제목, 3줄 요약, 출처 기사 목록(최대 3건: 기사 제목·원문 링크·발행 시각), 날짜, 카테고리, 이슈 ID

### US-04. 안전하고 정확한 주제

사용자로서 어떤 상황에서도 안전하게 꺼낼 수 있고 사실과 다르지 않은 문장을 원한다. 스몰토크 실패 리스크를 줄이기 위해서다.

- 정치, 종교, 젠더, 혐오, 사건·사고(사망, 범죄, 재난) 주제는 콘텐츠에 포함되지 않음
- 생성된 문장에 특정 집단이나 인물을 비하하는 표현 없음
- 요약과 스몰토크는 사람이 확인한 사실만을 바탕으로 생성됨
- 표현 4개 모두 동일한 안전 기준과 같은 확인된 사실을 사용

## 7. 기술 스택 (백엔드)

- **랭킹 데이터**: 네이버 데이터랩 검색어트렌드 API (키워드 검색량 상대값)

- **사실 검수**: 구글 시트 (AI 추출 결과 업로드, 승인된 사실만 다시 가져옴)

## 8. 콘텐츠 생성 파이프라인

1. **수집**: 네이버 공식 API로 트렌드 이슈·기사 제목·발췌문 수집 (본문 크롤링 X)
2. **사실 추출**: AI가 발췌문에서 사실 후보 1차 추출
3. **사실 검수**: 사람이 구글 시트에서 사실 여부와 AI 랭킹 헤드라인 확인·수정 (담당: PM, 부재 시 백엔드팀)
4. **생성**: 확인된 사실만 별도 AI에 넘겨 3줄 요약 + 스몰토크 표현 4개(기본 1 + 다른 표현 3) 작성, 승인된 사실의 원문 링크로 관련 기사 목록 구성
5. **재생성**: 실시간 생성 없음. 사용자가 다른 표현 보기를 누르면 4단계에서 미리 만든 표현으로 교체 (무료 AI 한도 대응, 11/9 결정)

## 10. 랭킹·콘텐츠 선정 기준

- **기준**: 키워드 검색량
- **방식**: 후보 키워드를 먼저 모은 뒤 데이터랩 API로 검색량을 조회해 순위를 매김
  - 데이터랩은 요청 단위 상대값(최댓값 100)이므로, 요청마다 공통 기준 키워드를 넣어 비교하는 등 산정 방식 설계 필요
- **뉴스 수집용 고정 검색어**: 네이버 뉴스 API는 검색어가 있어야 기사를 가져오므로 카테고리별 고정 검색어 8개로 매일 수집 (목록·변경 이력은 사실 검수 시트 '검색어 목록' 탭).
  - 선정 기준: ① 매일 기사가 꾸준히 나오는 넓은 단어 ② 20~30대 직장인이 점심·티타임에 꺼낼 만한 주제 ③ 정치·종교·젠더·혐오·사건사고 기사가 많이 딸려오는 단어 제외 ④ 다른 카테고리와 겹치지 않는 단어 ⑤ 계절 단어는 그 계절에만 사용
  - 첫 일주일은 검색어별 기사 수·검수 통과율을 기록해 교체 여부 판단, 목록 변경은 PM이 결정
- **후보 키워드**: 매일 6시 수집한 뉴스 제목에서 추출
- **헤드라인**: AI가 새로 작성(7시 전 생성)하고 7시 검수에서 승인된 것만 노출
- **검색량 비교**: 매 요청에 공통 기준 키워드를 넣어 그 대비 비율로 환산
- **집계 기간**: 전날 하루
- **갱신**: 하루 1번(6시 수집)
- **랭킹 검수**: 매일 상위 15개(TOP 10 + 예비 5개) 헤드라인을 검수하고, 제외된 순위는 11위부터 채움
- **카드 이슈 선정**: 카테고리 안에서 검색량 1위 이슈를 Today Pick 카드로, 2~4위를 예비 이슈로 사용 (예비 3개를 다 쓰면 처음 카드로 돌아감). 랭킹 TOP 10 이슈도 카드(요약·스몰토크)를 만들고, 카테고리 카드와 같은 이슈면 같은 카드를 사용. 랭킹 예비 5개는 TOP 10에서 제외된 자리를 채울 때만 카드 생성
- **카테고리 분류**: AI가 사실 추출 단계에서 경제·테크·문화·사회·환경 중 하나로 분류하고 7시 검수 때 확인
- **제외 주제**: 정치, 종교, 젠더, 혐오, 사건·사고(사망, 범죄, 재난)
- **3줄 요약**: 한 줄 40자 안쪽
- **관련 기사**: 요약이 여러 기사의 사실을 모아 만들어지므로 원문 하나 대신 출처 기사 목록 제공. 승인·수정된 사실을 원문 링크별로 묶어 사용된 사실이 많은 기사 순(같으면 최신 발행 순)으로 최대 3건
- **스몰토크 문장**: 부드러운 존댓말, 2줄 이내, 끝맺음은 자유(질문·감탄·사실 전달), 특정 브랜드·제품을 홍보하는 표현 금지 (브랜드명은 사실 전달로만 사용)
- **검수량**: 매일 카드 이슈 20개(카테고리 5개 × 4) + 랭킹 이슈 15개(헤드라인 + 사실 검수, 카드 이슈와 같은 이슈면 1건으로 계산), 최대 35건. 랭킹 이슈도 사실 검수가 필요해져 건당 검수 시간이 늘어남 (8시 오픈 전 검수·생성 시간 테스트 필요). 첫 주 운영 후 예비 이슈 개수 조정 검토
